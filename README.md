# Snow Forecast

A static website (no build step, no API key) with calibrated 15-day snow forecasts for every
Colorado, Utah and California ski resort, plus Whistler. Purgatory is the default. Installable on iPhone from Safari
(Share → Add to Home Screen).

## Run it locally

```bash
python3 -m http.server 8765
```

Then open http://localhost:8765.

## How it works

- `core.js`: forecast engine. Blends 7 models from [Open-Meteo](https://open-meteo.com/), applies
  calibration, converts snow water to inches with a temperature-based snow ratio, and splits
  each ski day into overnight (4 pm–9 am) and lifts-open (9 am–4 pm) snow.
- `resorts.js`: the mountains, their elevations and the weather stations used for each. Generated by
  `scripts/build-resorts.cjs` from [OpenSkiMap](https://openskimap.org) data plus hand-checked overrides.
- `app.js`, `history.js`, `index.html`, `styles.css`: the page.
- `data/calibration.json`: per-model correction factors and weights, made by
  `node scripts/calibrate.cjs`, which compares archived model forecasts with what NRCS SNOTEL
  stations (US) and Environment Canada (Whistler) measured since Nov 2022.

## Adding a mountain

Add it to `OVERRIDES`/`INCLUDE` in `scripts/build-resorts.cjs` if needed, rerun the script (see its
header), then `node scripts/calibrate.cjs`. Resorts without a SNOTEL station within 25 km borrow the
nearest calibrated resort's corrections (within 80 km), otherwise they run uncorrected.

## Powder alerts

`scripts/alerts.cjs` checks the mountains in `ALERT_RESORTS` (default `purgatory`) and sends a push notification through
[ntfy](https://ntfy.sh) when tomorrow has ≥ 4" by 9 am, any of the next 3 days has ≥ 6",
or the 3-day total is ≥ 12". `.github/workflows/powder-alerts.yml` runs it every evening.

1. Install the free **ntfy** app on your iPhone and subscribe to a long, random topic name
   (anyone who knows the name can read it).
2. In the GitHub repo: Settings → Secrets and variables → Actions → add secret `NTFY_TOPIC`
   with that topic name. Optional variables: `SITE_URL`, `ALERT_RESORTS` (e.g. `purgatory,wolf-creek`),
   and thresholds `OVERNIGHT_IN`, `DAY_IN`, `STORM_IN` can be set as env in the workflow.

`.github/workflows/calibrate.yml` recalibrates the 15 stalest resorts every week, so each resort is
refreshed about monthly while staying inside Open-Meteo's free limits.

## iPhone widget

`widget/snow-widget.js` is a [Scriptable](https://scriptable.app) widget. Setup steps and a
copy button are on the site at `widget.html`. It reads `data/summary.json`, which
`scripts/summary.cjs` builds during each deploy for the mountains in `WIDGET_RESORTS` (`.github/workflows/deploy.yml`, every 3 hours).

## Resort snow reports

`scripts/reports.cjs` reads official snow reports (last 24 hours, base, season, terrain open) from resort
websites that allow automated access and writes `data/reports.json` on each deploy. It currently covers
Wolf Creek. Other resorts use their nearest SNOTEL station for measured snow. Sites that block bots
(for example Purgatory's) are not read.

## Webcams

`cams.js` lists each resort's cameras (Brown Rice snapshot stills; tapping opens the live view).
Purgatory and Wolf Creek are set up. To add one, find the camera ids on the resort's webcam page
(`player.brownrice.com/embed/<id>`) and add them there.

## Models

The blend uses HRRR, NBM, ECMWF, GFS, Canadian, ICON and UKMO. ECMWF AIFS and NOAA AIGFS are fetched and
shown for reference (model table, forecast range) but kept out of the blend: in a backtest against SNOTEL
adding them didn't reduce errors. AIGFS is hidden at Whistler (`hideAt` in core.js): too little history to
calibrate, and it runs ~2x wetter than the corrected models there. Retest both after the 2026–27 winter.

## Upcoming Snow

`scripts/upcoming.cjs` runs on each deploy and writes `data/upcoming.json`: a lean 7-day forecast for every
resort (blend models only, 5 variables, about a quarter of the normal API cost) plus snow measured in the
last 48 hours (resort report, else the SNOTEL station, fetched for all stations in one request). It powers
the Upcoming Snow ranking and the "last 48 hrs" badge on favorite cards.

## Passes, drive times, storms, map

- `passes.js`: Epic / Ikon / Indy lineups (2025–26, from memory; update when lineups change).
- Drive times: the viewer taps "Use my location"; the browser's location (rounded to ~1 km, kept on the
  device) goes to the public OSRM router once for times to every resort. Estimates ignore winter closures.
- Storm tracker: groups resorts whose biggest 3-day window (≥ 6") starts within a day of each other.
- Snow map: Leaflet + OpenStreetMap tiles, dots sized and colored by the selected metric.
